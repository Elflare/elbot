# Co-agent 协作需求

本文记录已确认的目标行为，供实现和验收使用。[开发任务](tasks.md#co-agent-协作)记录进度。

## 目标

用户在一个窗口发起多项平行任务，各成员在同一工作区、各自独立的 Session 中并行工作。主 Session 是用户的默认对话对象和协作消息的展示入口。成员按分工独立使用工作工具，直接在同一块留言板协调。涉及共同修改的文件时，成员能留言说明负责范围、询问变动归属。

## 创建与分工

- 用户可以在当前主工作 Session 中用 `/co create <新增人数> <目标>` 手动发起。主 LLM 根据人数和目标给新增成员起名。用户的命令即为本次创建的授权。
- 每个协作组最多容纳 8 个 co-agent，主 Session 另计。已交付和空闲成员仍占名额。命令和工具共用额度，超出剩余名额时整批拒绝。例如已有 6 名成员时，最多还能创建 2 名。
- 主 LLM 也可以调用创建工具，必填参数为任务目标、成员名字列表。创建工具的风险等级是 `high`，按主 Session 已有的权限及确认策略处理。目标允许采用主 LLM 对用户需求的概括。
- 每个主 Session 拥有自己的协作组，再次创建时向现有组追加成员。置顶含三项：非空任务目标、系统维护的完整成员名册、可为空的自由正文。正文可写工作约定、交接说明等任意文本。首次创建时正文为空，追加成员时保留现有正文。系统分配 Session ID、保存置顶后广播开工。模型自己的系统提示词 meta 提供真实 Session ID。
- 子成员的外部对话输入来自留言板，自身模型历史、工具调用和结果按自身 Session 保存。主窗口里的普通用户发言、主 LLM 私下与用户讨论的上下文均不自动复制给成员。

## 用户命令

用户命令和补全见[命令速查：Co-agent 协作](../docs/commands.md#co-agent-协作)。所有操作以当前绑定选择协作组；状态只返回组内成员的运行阶段与待处理输入数，不切换绑定。
## LLM 工具接口

通过 `discover_tool` 发现 `coagent`，按角色激活具体操作；只有主模型可以创建、修改置顶及移除成员。调用者和所在组由执行中的 Session 提供。操作参数中的 Session ID 只表示定向收件人或待移除成员。
### `coagent_create` · 创建成员

主 LLM 可调用，风险等级为 `high`。单次调用创建整个名字列表，子成员数量取列表长度。名字由主 LLM 给出，须为组内唯一的单行显示名。目标可以在同一段文本内明确各成员的分工。

```json
{
  "type": "object",
  "properties": {
    "goal": {"type": "string", "minLength": 1, "description": "必填置顶目标，可包含各成员分工。"},
    "names": {"type": "array", "minItems": 1, "maxItems": 8, "uniqueItems": true, "items": {"type": "string", "minLength": 1}, "description": "本次新增成员的名字，按创建顺序排列。"}
  },
  "required": ["goal", "names"],
  "additionalProperties": false
}
```

调用示例为 `{"goal":"修复者负责改动，验收员负责验证。","names":["修复者","验收员"]}`。成功结果包含置顶更新编号与新成员的名字、Session ID；新旧成员均可在板上读取更新后的完整名册。创建失败时整批回滚。

### `coagent_post` · 发留言

主和子 LLM 均可调用。省略 `target_session_id` 表示广播；提供时只向该 ID 对应的成员推送。系统根据发言 Session 自动署名。两种留言均写入完整板历史，主窗口都展示一次。

```json
{
  "type": "object",
  "properties": {
    "text": {"type": "string", "minLength": 1, "description": "留言正文。"},
    "target_session_id": {"type": "string", "minLength": 1, "description": "可选，本组当前收件 Session ID。"}
  },
  "required": ["text"],
  "additionalProperties": false
}
```

广播示例为 `{"text":"默认值已经确定，请按置顶分工继续。"}`。定向示例为 `{"target_session_id":"qq334","text":"请检查空配置。"}`。返回已写入留言的编号、作者、目标及原文。目标无效时不产生留言。

### `coagent_pin` · 修改置顶

仅主 LLM 可调用。至少提供 `goal`、`text` 中的一项；省略的字段保留。显式传 `"text":""` 清空自由正文。两个字段一起更新时原子保存，只产生一个更新编号和一次广播。系统维护名册，返回更新后的完整置顶。

```json
{
  "type": "object",
  "properties": {
    "goal": {"type": "string", "minLength": 1, "description": "新的任务目标及分工，省略时保留当前值。"},
    "text": {"type": "string", "description": "任意置顶正文。可多行，空字符串清空，省略时保留当前值。"}
  },
  "anyOf": [{"required": ["goal"]}, {"required": ["text"]}],
  "additionalProperties": false
}
```

只改目标用 `{"goal":"修复空配置并补充回归验证。"}`，只清正文用 `{"text":""}`。同时更新的示例为 `{"goal":"通过旧配置回归测试","text":"验收样例在 fixtures/legacy。\n改动前请先留言。" }`。

### `coagent_board` · 读留言板

主和子 LLM 均可调用。每次都返回置顶的目标、完整名册与自由正文（可为空）。`after` 是调用者上次看到的组内留言编号；本次只返回编号严格大于它的记录，按升序排列。没有新增时返回空留言列表。

```json
{
  "type": "object",
  "properties": {
    "after": {"type": "integer", "minimum": 0, "default": 0, "description": "仅返回此编号之后的留言，0 表示全部。"}
  },
  "additionalProperties": false
}
```

全量读取用 `{}`，从第 13 条之后读取用 `{"after":13}`。结果包含主 Session ID、完整置顶及留言记录。每条记录包括编号、作者、收件范围、正文和置顶更新标记。全量和增量均包含定向给其他成员的留言。

### `coagent_remove` · 移除成员

主模型可调用，风险等级为 `high`。唯一参数 `target_session_id` 必填且非空。停止并移除本组指定子成员，保留 Session 和历史留言，释放名额。主会话和非本组成员都不能作为移除目标。

## 留言板与主窗口

| 动作 | 用户在主窗口看到 | 模型自动收到 |
|---|---|---|
| 用户普通聊天 | 主对话 | 主 LLM |
| 子成员回复用户 | 带名字的回复正文，如 `[修复者]：已修复配置读取。` | 正文归发言成员自己的历史 |
| 广播留言 | 一条带编号和作者的留言 | 全组，包括主 LLM 和已交付的成员 |
| 定向留言 | 一条带编号、作者和目标的留言 | 指定 Session 的 LLM |
| 更新置顶 | 一次置顶更新 | 全组 |

所有成员均可发帖、查看完整留言板，也可按组内留言编号读取新增内容。定向决定主动推送范围，全组仍能主动读到这条留言。例如 `#13 [监工] → [修复者]：请检查空配置。`

模型通过带真实作者和编号的模拟用户消息收到板更新。忙碌成员通过 pending 在可接收时处理，空闲或已交付的成员被新留言唤醒。主窗口对每条留言只展示一次。子成员普通回复不写留言板；工具记录、工具结果和思考过程留在成员自己的执行记录中。

## 工具权限和生命周期

- 只有用户和主 LLM 可主动创建、移除成员和修改置顶。每次成功修改置顶都广播。只有主 LLM 可用 `ask_user`；子成员需要用户决定时发留言，用户也可以定向留言回答。
- Co-agent 对所有有权使用的工具免逐项确认，包括 `high`、`critical`。通过已有权限及工具自身的执行检查后，成员直接执行。主 LLM 沿用主 Session 的确认策略。
- 继续使用进程级 `/stopall` 停止活动请求。组、名册和留言板保留，新留言仍可唤醒成员。客户端断线后用户回主窗口继续协作。
- Session 压缩派生新 ID 时延续组内成员身份及投递归属。板中已发布的历史保留当时的署名和目标。
- 仅板留言唤醒不触发自动压缩。子成员达到上下文阈值时，在下一次模型调用前由系统在板上报告、通知主窗口并退组；不要求原模型生成总结，也不自动补员。

## 验收

1. 从一个窗口创建多名成员，验证并行执行、共同工作区、独立历史和首次开工时的完整名册。
2. 两名成员并发发帖，编号唯一。主窗口收到一份展示；广播、定向、全量读取和增量读取各自符合上表。
3. 检查主 LLM 的实际输入，验证成员普通回复和发给其他成员的定向正文只会按既定路径出现。
4. 分别更新目标和正文、同时更新两项、清空正文、追加成员。检查省略的字段及已有正文按规则保留，一次提交只广播一次。验证主、子专属工具的发现和实际调用权限。
5. 覆盖成员交付后再次被唤醒、压缩期间收到留言、主窗口重连、并发执行中停止及停止后的新留言。
