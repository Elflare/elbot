### 实施约束

- 业务明确提供结果、等级与错误，来源事件保留各操作事实；日志回调、信号和中心不从错误链、文案或事件名反推分类。
- 日志链路保持错误对象和结构化载荷，只有最终写入阶段才格式化错误、提取诊断、脱敏、限长及序列化。发布后的错误只读，可变错误由来源复制其具体结构。
- 沿用现有包，不新增共享错误分类器、取消判断器或错误树检查设施。业务直接记录或通过本模块已有日志回调记录，统一交给全局日志信号和日志中心。
- 所有包、文件位置、包名、文件名、函数名和变量名必须与用户讨论确认；可以提出候选，不能自行定案。待讨论项见 [具体契约与命名](signals-and-logging.md#已有代码位置与实施前待确认项)。
- 保留重试与权限规则、平台连接全局信号、同步业务持久化、队列和共同 30 秒退出预算，不改写历史日志，不自动提交。代码地图和架构随实际代码变化更新，不能提前描述为已经实现。

### 步骤 1：契约与公共链路

- [ ] 与用户确认尚未定案的身份类型及存在性表示、结构化详情类型、类别枚举声明、来源事件完整字段，以及受影响函数、变量和文件位置；确认结果写回设计文档后实施。
- [ ] 将 `ResultStatus`、`LogCategory` 改为受验证的枚举；零值结果表示未声明，非法值走设施诊断，不能推导或修改业务结果与等级。
- [ ] 落实已确认的 `EventName`、`BusinessAttributes`、`Identity`；固定身份不再混入附加属性，保留来源身份及显式空值优先语义。
- [ ] 支持结构化 `Detail` 和通用诊断载荷；删除发布阶段错误文本快照，主错误与附加错误保持对象，不能以文本重新包装成 `error`。
- [ ] 在最终写入阶段统一错误格式化、通用诊断、详情展示、脱敏与限长；防止附加错误和嵌套属性绕过非 DEBUG 详情限制，保护正式字段并防止重复键歧义。
- [ ] 验证发布、派发和排队不调用错误格式化；覆盖枚举合法性、错误所有权、结构化载荷快照、身份、等级过滤及记录上限。
- [ ] 完成 gofmt 和相关包测试，记录真实验证结果；公共契约变化同步检查消费者编译和全量测试。

### 步骤 2：全部来源迁移

- [ ] 逐个检查 Agent、工具、Session、模型客户端与 Model Manager、Hook、平台、发送、Cron、Elnis、媒体、命令、通知、维护及 App 的直接发布点和来源事件。
- [ ] 在业务发生成功、取消、拒绝、跳过或失败的位置明确结果并沿事件传递。日志回调只按来源事实构造记录，移除从错误链重新猜测结果的逻辑；普通提示与进度允许不声明结果。
- [ ] 按已确认的完整事件契约迁移结果和错误字段；不同操作分别保留结果与错误，需要汇总时由业务决定。不得仅列 `CallError` 等示例后自行扩展结构，也不批量重命名无关局部变量。
- [ ] 修复工具解析阶段丢失策略拒绝事实；区分拒绝、工具不存在、配置缺失和执行失败，覆盖 Runner 与直接执行入口。
- [ ] 修复调用取消掩盖持久化失败，以及调用成功、保存失败被误报上游失败的链路；保留 Chat 部分输出且返回空错误时的真实结果。
- [ ] 检查工具调用与记录保存、命名与兜底保存、回复发送与持久化及消息关联等组合操作，拒绝或取消不能覆盖独立失败。
- [ ] 将主错误统一迁入 `Error`，清除日志链路提前 `Error()`、提前 JSON 编码及重复主错误诊断；完成全部来源迁移后删除自由 `error` 字段的过渡支持。
- [ ] 保留重试次数、延迟与回退等业务事实，重试机制仍归客户端；回归无通知订阅者不漏日志、过期重试通知不显示、Hook 原始失败不重复记录。
- [ ] 通过真实业务入口验证结果和错误传递，再验证落盘等级、诊断、身份及查询；运行相关测试和公共接口变更后的全量测试。
