# 任务清单

## 信号与日志系统整改

详细设计见 [信号与日志系统设计](signals-and-logging.md)。本文只跟踪当前目标下的任务，不累加旧轮次的阶段记录。

状态：九字段契约、text／JSON 正文和 JSONL 写入要求已确认并写入设计文档。本次只更新文档，Go 代码尚未修改，公共底层、业务来源及命令迁移均待后续实施；不运行验证，交由用户审阅。已完成的预载事件名修复继续保留，不代表新的契约整改已完成。

### 实施约束

- 先文档、再公共底层、再迁移来源和查询命令；允许业务暂时编译失败，不为维持全仓编译提前迁移，全部步骤完成后再做完整测试。
- 所有日志只用 Category、Level、Module、EventName、Type、Content、ContentLimit、Identity、ResultStatus 九字段；时间由中心自动记录。底层字段注释写明用途、零值和约束。
- 不保留摘要、详情、错误对象、任意属性或额外信息入口。原始错误留在业务中，来源把错误原因和必要诊断写入 Content；日志回调、信号和中心不猜业务结果，日志与 notify 分开。
- 普通日志优先 text，按 Unicode 字符截断，默认 256；需要字段查询和统计的来源填写 JSON 并自行控制体积。JSON 不按 ContentLimit 截断，新记录统一写 JSONL。
- 沿用现有包和接口，不新增共享错误分类器、取消判断器、错误树检查设施或任意业务对象转换器；具体名称见[已确认的位置与实施接口](signals-and-logging.md#已确认的位置与实施接口)，未讨论的新名称仍需确认。
- 保留重试与权限规则、平台连接全局信号、同步业务持久化、队列和共同 30 秒退出预算，不改写历史日志，不自动提交。代码地图和架构随实际代码变化更新，不能提前描述为已经实现。

- [ ] 在现有位置实现九字段契约与定义注释；移除旧摘要、详情、错误对象、自由属性及通用诊断接口，不留兼容入口。
- [ ] 实现 `LogCategory`、`LogContentType`、`ResultStatus` 整数枚举及 `Valid`／`String`，非法契约返回提交错误并走独立 stderr。

- [ ] 逐链路确认并迁移来源实例事件的完整结果和错误字段；不同操作分别保留事实，需要汇总时由业务决定。不得仅列 `CallError` 等示例后自行扩展结构，也不批量重命名无关局部变量。
- [ ] 修复工具解析阶段丢失策略拒绝事实；区分拒绝、工具不存在、配置缺失和执行失败，覆盖 Runner 与直接执行入口。
- [ ] 修复调用取消掩盖持久化失败，以及调用成功、保存失败被误报上游失败的链路；保留 Chat 部分输出且返回空错误时的真实结果。
- [ ] 检查工具调用与记录保存、命名与兜底保存、回复发送与持久化及消息关联等组合操作，拒绝或取消不能覆盖独立失败。
- [ ] 所有来源改填九字段，原始错误留在业务处理链路，日志正文写明错误原因和必要诊断；删除来源对旧日志错误、属性和诊断接口的依赖，不让日志承担 notify 职责。
- [ ] 普通运行日志优先 text；`llm_usage`、需要业务字段筛选的审计记录及 Elnis 业务事件使用来源构造的 JSON，来源先控制 JSON 体积。
- [ ] 迁移 Reader 兼读 JSONL 和历史格式，迁移 `/log`、`/audit`、`/elwisp`、`/usage`；按 Type 解析，JSON 业务条件在计入数量前匹配，不覆盖外层公共字段，不把异常用量默默当零。
- [ ] 保留重试次数、延迟与回退等业务事实，重试机制仍归客户端；回归无通知订阅者不漏日志、过期重试通知不显示、Hook 原始失败不重复记录。
- [ ] 通过真实业务入口验证各操作结果及错误原因，再验证落盘等级、正文、身份及查询；运行相关包测试，完整回归留到步骤 3。
