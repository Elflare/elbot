## 代码精简审查

目标：保持功能及可观察行为不变，沿调用链删除无用代码、重复状态、过度防御和多余转换。用户文档不改。前几轮只算局部已精简，已有结论复用，有新证据再复查。

### 路线与进度

先通过 `internal/app/wiring.go` 确认装配关系，然后按顺序推进；每段可以分多轮。

- [x] ① 输入与分流：平台输入转换 → Agent 消息分发 → 命令／普通消息分流 → 执行入口。入口：`internal/platform/agent.go`、`internal/agent/input/message.go`。
- [x] ② 执行准入与生命周期：`agent/execution/execution_admission.go` 准入 → `request/manager.go` 请求与取消 → `turn/execution.go` 执行状态。
- [x] ③ 单轮准备与模型调用：`agent/dialogue/runner.go` 单轮编排 → `agent/chat/`、`agent/responses/` 协议循环 → `modelmgr/`、`llm/` 模型选择与请求。
- [x] ④ 工具调用与结果提交：`agent/dialogue/tool_execution.go` 工具入口 → `tool/execution/runner.go` 批次执行 → `agent/dialogue/commit.go` 结果提交。
- [x] ⑤ 回复与平台投递：`agent/dialogue/reply_commit.go` 回复提交 → `agent/output/output.go` 输出处理 → `platform/dispatch/router.go` 发送路由。
- [x] ⑥ 会话与上下文：Session 绑定／切换 → 历史加载 → 压缩／派生 → 存储。检查重复快照、状态归属、无消费者字段，保留事务和并发准入语义。
- [x] ⑦ 媒体生命周期：输入归档 → 持有／引用 → 模型使用／平台发送 → 释放／清理。检查重复导入、转换及资源所有权。
- [ ] ⑧ 后台任务：Cron 调度／Elnis 接收 → Agent 执行入口 → 报告落库 → 投递／恢复。复用前台结论，深入后台特有的重试、接管、去重和恢复。
- [ ] ⑨ 扩展与基础设施：Hook 规则／运行时 → 命令／补全 → 配置／装配／关闭 → 信号／日志。检查契约、转发层及重复配置、生命周期状态，并核对遗漏范围。

路径未写完整时相对 `internal/`。存储、权限、适配器和内置工具随对应链路按需深入；遇到其他支线先记入口，不临时跳转展开。

### 执行规则

1. 每轮固定入口和终点，追踪输入、状态、返回值、资源所有权及校验责任。
2. 候选项先用 LSP 查引用，再用磁盘搜索核对接口调用、序列化、恢复路径和测试用途。
3. 核对成功、失败、取消、部分成功及重入行为；改变行为的事项单列，不混入精简。
4. 每轮更新已看范围、可删项及依据、保留项和下一入口。没有可删项也算有效审查。
5. 函数短、单一调用方、仅测试读取均不能单独作为删除理由。
6. “继续看”沿路线审查；“改”实施当轮确认项。修改后运行 gofmt、diff 检查和相关测试；公共接口变化或影响不明时扩大测试。
