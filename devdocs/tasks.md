阶段 2 验证记录：

- 全部业务日志通过 `events.EmitLog` 发布，Agent／Session／Model Manager 自行维护同步日志投影；已删除 App 日志转换文件和旧 Logger／Audit 注入入口。

- gofmt、`go test ./...` 通过；signal、events、logging、agent、session、modelmgr、hook、notification、app、cron、elnis、llm、platform、delivery 相关包及其子包的 race 测试通过。

阶段 3 验证记录：

- Reader 使用 64 KiB 反向分块扫描，真实读取量测试确认尾部一条命中只读取一个块；满足条数后不再解析更旧的超长行或打开更旧的文件。
- 覆盖跨块中文、LF／CRLF、无末尾换行、16 MiB 行边界、跨日组合筛选、事件时间与写入顺序不同、固定读取范围、取消及读取错误。
- 命令测试覆盖审计旧选项删除、事件名原样筛选、Hook 模块条件交集、帮助与补全；真实全局信号落盘后验证摘要、DEBUG 详情、上游失败审计和 WARN／ERROR 下的用量统计。
- race 回归发现旧重试通知测试依赖已失效的队列下标；改为阻塞全部观察队列后，该取消场景连续运行 20 次通过。
- gofmt、全量 Go 测试、signal／events／logging／command/builtin／app 的 race 测试及依赖边界检查通过；既有装配清理、背压和退出预算回归通过。中文文档、架构与代码地图已同步。

保留现有共同的 30 秒退出预算、同步业务持久化和日志轮转配置；不修改远程部署，不自动提交。

## 日志审查整改与平台全局信号

状态：设计已确认，代码待实施。详情见 [审查整改设计](global-signals.md#审查整改设计待实施)。本次文档准备只更新本文件和设计文档；代码地图、架构、用户文档及 CHANGELOG 随实际代码改造更新，不提前声明整改完成。

| 阶段 | 工作内容 | 验收条件 |
| --- | --- | --- |
| 1 | 日志级别与诊断修复、文件职责拆分、事件和方法命名整理 | 重试 WARN、最终失败 ERROR；命名失败审计保留详情；事件标识与文案独立；职责及依赖边界清晰 |
| 2 | 平台连接事实改为全局信号，消费者自行订阅 | 无 App 转发；既有 Hook、Cron 行为不变；启动、订阅释放及关闭回归通过 |

- [ ] 整改阶段 1：日志规则、职责与命名。
  - 检查本次日志迁移涉及的失败记录：每次重试失败 WARN，最终失败 ERROR，预期取消不升级，权限拒绝等正常策略结果单独判断。
  - 命名的最终上游失败通过 ERROR 审计保存通用诊断，覆盖 INFO／WARN／ERROR 配置；普通运行正文仍遵循 DEBUG 详情规则。
  - 按设计整理 App、Session、Model Manager 的文件职责；显式声明稳定事件名，修正含糊方法名、无效错误返回和内部回调可见性。
  - 保留客户端重试、实例信号和通知；验证无通知订阅者仍有重试日志，调用结束后不显示过期通知。帮助、补全和查询随事件名同步，不增加旧名称兼容层。
- [ ] 整改阶段 2：平台连接全局信号。
  - 适配器直接发布，Hook 协调模块和 Cron 自行管理订阅及队列；删除 App 逐个适配器转发的接线。
  - 消费者先订阅、平台后启动；覆盖连接和重连、重复连接、失败清理、关闭后不再消费，以及既有 Hook 执行和 Cron 补执行。
  - 每阶段运行相关测试、race 测试及依赖边界检查；公共接口改造后运行全量测试，并更新相应文档和完成状态。

不新增 Go 包，不新增全局重试信号；只迁移已有平台连接事件，不扩展断开、恢复等新事件。日志查询、维护清理等需要结果的同步调用及活跃 Binding 的实例边界保持不变。
